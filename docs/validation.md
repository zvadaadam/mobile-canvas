## Declutter, restyle and open --screen · September 10, 2026

The repository was reduced to the native canvas and its runtime. Removed: the Expo 57 simulator adapter (`apps/native`, `apps/preview`), the browser editor (`src/web`, Vite, the Expo styleguide and font packages), the verification scripts, the Daylight and Tempo projects, six superseded documents and their tests. The host launcher, build script, Metro loopback bridge and MCP terminal client were rewritten in TypeScript under `src/runtime/host` and `scripts/`; the only non-TypeScript source left is the `bin` entry, Metro's CommonJS config, the Expo config plugin and the Swift host. Root dependencies went from twelve packages to five. After the change: `npm run check`, `npm run check:studio` and 24 tests pass; the workout project opens with 25 of 25 frames ready and no console errors.

The canvas was restyled to the Expo look recorded in [design-system.md](design-system.md): a 52 pt toolbar with the wordmark, project name, a black **New screen** pill and grouped symbol buttons with tooltips; frame names above the frames, counter-scaled with the zoom so they read at 12% as at 100%; one-pixel borders and a soft shadow per frame; a status bar with a readiness dot; an inspector with captioned bordered fields, a black primary pill and outlined secondary pills; keyboard shortcuts for zoom, fit and the inspector. Captures at 100% and at the fitted 12% and 19% overviews were inspected on this Mac.

`open --screen <key>` (runtime `studio/open` with `screen`, MCP `canvas_studio_open`) reveals one frame at 100% as soon as the host lays out. The first three attempts landed on the wrong part of the board. The host now reports its visible board rect (`host.viewport`) and its last diagnostic line (`host.note`), and that note showed the cause: at the moment of the reveal the Today frame measured 5220 × 7408 instead of 402 × 874. The frames are `UIViewController` views, which autoresize with their superview by default, and the board's bounds grow after the frames are placed, so every frame was stretched by the board size until the next half-second refresh reset it. With autoresizing disabled the reveal computed the expected offset (894.5, 882 for a 1925 × 1306 viewport) and the capture showed Today centered and selected. Lesson recorded: measure through UIKit's own geometry and report it, rather than trusting the values just assigned.

Not verified today: pointer interaction on the restyled frame names beyond selection, the inspector's text editing after the restyle, and the Conductor **Canvas** action, whose long-running runtime predates these changes and must be restarted.

## Running the app in place instead of copying it · September 9, 2026

Asked whether the canvas could work without replicating the codebase, the import gained a linked mode and the workout project was converted to it. `import --link` records the app as `origin.mode: "linked"`, points the app's `@/` alias at its own `src/` (an absolute alias target the executor only accepts inside the linked app), and `resolver.modules` keys that are app paths (`src/theme/colors.ts`) override that file wherever it is imported, by alias or relatively; a path the app does not have becomes an added file. Metro watches the app directory, resolves its JavaScript-only packages from its own `node_modules`, and refuses its native packages, which must come from the host.

Converting the workout project deleted the 86 unchanged copies and kept 38 project files: 19 overrides (theme scope, fixture-backed store, SDK 54 rewrites, polyfill), the new This week screen, and 18 canvas adapters, all mapped by app path. The app's own catalog package now serves it from the app's `node_modules`; the copied package and the project's `package.json` are gone. Opened on the rebuilt host, all 25 frames reported ready with no Metro errors, the inspected capture matched the copied version, `doctor` passed, and `diff` listed exactly the 19 diverged files, the added screen and the canvas-only adapters. A unit test covers linked import, an alias outside the app being refused, path overrides, review and apply.

What this establishes: the canvas can run an unmodified app tree with a thin overlay. What still costs effort is the overlay itself, which is app-specific where the app relies on a database, module singletons or SDK APIs the host lacks; the remaining generic pieces (router, sqlite passthrough, symbols, dimensions, media and system stubs) are candidates to ship with the product. Editing the linked app itself is not tracked by the runtime's code version, only by Metro's refresh.

## Flow connectors and the silent exits · September 9, 2026

Each screen's `links` now draw as connectors on the board (Flow toolbar toggle): curves from the nearest edges with an arrowhead at the destination, reverse edges offset, the selected frame's edges in blue, and a navigation reported by a frame pulses its edge in green because the focus command now carries the origin frame. The Expo Workout project's links were rewritten from the screens' actual `router` calls (64 edges, in-content navigation only); doctor reports no unknown links. An inspected 42 % capture shows the connectors between the 25 frames with Today's seven outgoing edges highlighted.

The first automatic arrangement chose the wrong entry (the first unlinked screen in document order was Workouts) and stacked nine screens in one column. Arrange now picks the unlinked screen that reaches the most of the app, lays a centered row per depth top-down, hides a variant's edges unless it is selected, and draws return edges dashed. The inspected result reads as a tree: Introduction, then Today, Workouts and This week, then the nine screens they open, then the detail screens, with the five design variants in a band underneath. Edges from Today still fan across its row, which the layout cannot avoid; they are the app's real structure.

The two silent host exits were the launcher: it polled the runtime with a one-second timeout and closed the native session on the first slow answer, which a single-threaded runtime produces while hashing 150 files or answering a diff. The launcher now waits four seconds, tolerates five consecutive misses, and records the reason in studio state; the exit reproduced once more before the fix (as `The operation was aborted due to timeout`) and not after it during the following captures.

## Screen focus and agent inspection — September 10, 2026

The native canvas now fits a selected screen with space for its title and inspector, using a 220 ms interruptible camera move. Keyboard fits remain immediate. Native window geometry updates only when changed, clipping masks are reused, and unchanged document polling skips frame reconciliation. A first pointer hit on an unselected frame focuses it before native content can activate; Fit All restores that focus-first behavior even for the selected thumbnail.

Verified native images on the six-screen Hot Chocolate linked project and the 25-screen Workout reference. Eight sequential MCP inspections across all six Hot Chocolate screens returned current, error-free 804 × 1748 images in 915–1025 ms on a warm host. Whole-canvas pixels show the dashed inspection ring and “Captured for agent” label; the indicator subsequently clears. A repeated inspection exposed a stalled screen report, so screen requests now abort after four seconds and retry without unmounting content.

Both native SDK 54 and matched SDK 56 builds compile. Root and host TypeScript checks and 40 runtime tests pass, including settling, concurrent inspection rejection, old-host rejection, human-focus interruption and presence expiry. This verifies functionality and native pixels; input-to-paint latency has not been benchmarked against Figma.

Final native interaction checks confirmed that Fit All restores the frame focus control and activating it returns the selected screen to 100% within the viewport. Coordinate-based drag testing was unavailable because the computer-use driver returned `noWindowsAvailable` for the iOS-on-Mac window, so background-drag smoothness remains a hands-on validation item.
